## 1. Что это

Практический курс про работу с ИИ-агентом в табличном редакторе: формулы, сводные, графики,
бюджет — текстом, без знания синтаксиса функций. Аудитория: офисные сотрудники,
предприниматели, начинающие аналитики. Входной уровень: «открыть файл, ввести данные,
отфильтровать». Платформа: Moodle. Полностью без преподавателя, оценка автоматическая.

Методическая основа — `План_интенсива_Excel_агентV2.docx` (6 блоков × 60 мин, банк запросов
З1.1–З6.5, квизы, рубрики, варианты датасетов A/B/C). Мы перекладываем его в формат Gecko:
**9 уроков**, каждый = озвучка (edge-tts) + анимированные стик-сцены + карточка практики.

Сквозной кейс: торговая компания «Вектор», продажи 2025 → бюджет 2026.
Герои: **Аня** (сотрудник, глаза слушателя), **Агент** (оранжевый робот `#d97757`),
**Дмитрий** (руководитель, «отчёт к пятнице»).

## 2. Правила нейтральности (утверждены Ольгой, нарушать нельзя)

- Ни производителей, ни продуктов, ни нейросетей по имени.
- **Слово «Excel» запрещено**: только «табличный редактор», «редактор таблиц»,
  «книга таблиц», «файл таблиц».
- Исключение: имена учебных файлов в карточках практики (`sales_2025.xlsx`, `warmup.xlsx`) —
  студенту нужен точный адрес файла.
- В сценах: «р.» вместо «₽» (знак рубля не входит в subset шрифта), кириллица — локальный
  Balsamiq Sans (атрибут `no-font`), без чужих логотипов.
- Сценарий: 280–350 слов, строки `A:`/`B:`, без длинного тире, без «надо/нужно/должен/
  обязательно/следует», к слушателю на «вы».

Скриншот конкретной сцены панели (для визуальной QA): в консоли страницы
`document.querySelectorAll('figure[data-scene]').forEach(f=>f.classList.toggle('current', f.dataset.scene==='<id>'))`,
затем `dispatchEvent(new MouseEvent('click'))` на `<stick-scene>` и снять `.stage` через CDP clip.

⚠ **ГРАБЛЯ СКРИНШОТОВ (стоила трёх кругов QA).** Три отдельные ловушки:

1. **Viewport маленький** (~762×428), а панель `.stage` лежит на y≈363 → при
   `captureBeyondViewport=false` clip уходит за viewport, в кадре только верхняя полоса.
2. **При `captureBeyondViewport=true` координаты clip трактуются ОТНОСИТЕЛЬНО ДОКУМЕНТА**,
   а `getBoundingClientRect()` даёт координаты относительно viewport. После `scrollIntoView`
   надо передавать `y = rect.y + window.scrollY`, иначе в кадр попадает верх страницы
   (заголовок, плеер), а сцена остаётся узкой полосой снизу.
3. **`Emulation.setDeviceMetricsOverride` надо вызывать ПОСЛЕ `new_tab`/`wait_for_load`**,
   иначе метрики не применяются (dpr остаётся 1) и снимок выходит 707×422 вместо 1410×844.
   Метрики могут «поплыть» между вызовами — перед съёмкой печатать
   `innerWidth + 'x' + innerHeight + '@' + devicePixelRatio` и сверять.

Рабочий рецепт (проверен):
```python
new_tab('http://127.0.0.1:PORT/preview.html'); wait_for_load(); time.sleep(2)
cdp('Emulation.setDeviceMetricsOverride', width=760, height=1200, deviceScaleFactor=2, mobile=False)
# для каждой сцены:
js("...toggle('current', f.dataset.scene === '<id>'); el.dispatchEvent(new MouseEvent('click',{bubbles:true}));
    document.querySelector('.stage').scrollIntoView({block:'center'})")
time.sleep(4.5)                                   # dur сцены 5.5–7 с, нужна середина
geo = js("({x: r.x, yDoc: r.y + window.scrollY, w: r.width, h: r.height})")   # ВАЖНО: + scrollY
cdp('Page.captureScreenshot', format='png', captureBeyondViewport=True,
    clip={'x': geo['x'], 'y': geo['yDoc'], 'width': geo['w'], 'height': geo['h'], 'scale': 1})
```

**Самоконтроль кадра ПЕРЕД отправкой на QA** (PIL): размер должен быть ~1410×844, доля тёмных
пикселей (r,g,b < 90) — больше ~0.8%, оранжевых (робот #d97757) — ~0.85% в сценах с роботом
и 0% там, где робота по замыслу нет. Если 0% — кадр пустой, переснимать (обычно помогает
повторный new_tab + переустановка метрик).

**Ещё одна ловушка:** `js()` уходит в ТЕКУЩУЮ вкладку. Если между вызовами открывали другую
страницу, селекторы вернут null (`Cannot read properties of null`). Перед диагностикой делать
`new_tab(<нужный url>)` и проверять `document.title` / число `figure[data-scene]`.

**rAF в headless тикает** (проверено: ~105 кадров/с), но фоновый canvas всё равно удобно
дёргать принудительно через `window.__bgDraw()`.

## 5. Грабли и находки (стоили времени, не повторяй)

**Датасеты**
- Округление — **half-up через `Decimal`**, не `round()` Python. Банковское округление давало
  расхождение в сумме бонусов (866106.94 вместо авторских 866107.90). Правило автора эталона:
  `Бонус = half_up(сырая_выручка × ставка)` — от НЕокруглённой выручки, 31 строка расходилась
  при округлении сначала.
- Правила расчётных колонок калибруются построчно по `reference_b3.xlsx` (функция `calibrate`),
  несоответствий должно быть 0. Регрессия варианта A — функция `check_regression`.
- `write_file` не перезапишет файл, прочитанный с offset/limit: либо дочитать до конца,
  либо `rm` + запись заново.

**Озвучка edge-tts**
- Сервис **троттлит серии запросов**: одиночная реплика проходит с 1-й попытки, та же реплика
  в потоке после нескольких предыдущих — стабильно `NoAudioReceived`. Лечение: каждая реплика
  отдельным subprocess (`--one`), пауза 8–12 с между репликами, кэш частей в `_tts_parts/`
  (перезапуск догоняет, а не начинает заново).
- Параметр `rate="-4%"` ломает запрос (`NoAudioReceived`) — не использовать.
- `ffmpeg concat` требует **абсолютные** пути в list-файле (иначе ищет относительно Temp).
- Голоса: `ru-RU-SvetlanaNeural` (Аня/ведущая), `ru-RU-DmitryNeural` (собеседник).
  В ru-RU других голосов у edge-tts нет.

**Озвучка Яндекс (ударения)**
- Ударение задаётся знаком `+` перед ударной гласной прямо в `script.txt` (`вечер+а`, `вест+и`,
  `марж+у`, `стр+оки`, `в+иду`, `д+о`). SpeechKit v1 эту разметку понимает: проверено на паре
  «зам+ок» / «з+амок» — длины аудио 1,10 и 0,86 с против 0,86 с у нейтрального «замок».
- **Плюс нельзя оставлять в видимом тексте.** В `timings.json` пишутся два поля: `src`
  (строка с разметкой, по ней ловится правка) и `text` (чистый, идёт в расшифровку на странице).
  Сравнивать `src` со старым `text` бессмысленно: `+` не меняет отображаемый текст, и кэш
  не инвалидируется — на этом потерял один прогон.
- **SpeechKit недетерминирован побайтово.** Один и тот же текст даёт разные mp3 (длина
  плавает ±0,03 с и изредка отличается «дубль» озвучки на ~0,1 с). Поэтому `verify_tts_parts.py`
  сравнивает ДЛИТЕЛЬНОСТЬ с допуском 0,15 с, а не md5: md5-сверка даёт ложные «расхождения»
  даже на только что сгенерированных файлах.

**Стик-сцены и панель**
- Масштаб сцены: `S = min(elemH/230, elemW/scene.width) × zoom`; земля `gy = elemH − 38·S`;
  вверх от земли доступно `gy/S` юнитов, по бокам `±elemW/(2S)`. При панели 705×380 и zoom 1.3
  это **−139 сверху и ±164 по бокам** — всё, что дальше, обрезается.
- `bubble()` рисуется **ВВЕРХ** от переданного y (высота = size+12). Ставить y ≤ −134 нельзя:
  верх облачка уйдёт за панель. Рабочая позиция y ≈ −114.
- Фигура ≈120 юнитов высотой → реально достижимая доля панели ~65%. Больше — только убирая
  верхний контент.
- `figure` без `inset:0` схлопывается по ширине → canvas узкий → масштаб считается неправильно
  и фигуры мелкие. Всегда растягивать контейнер.
- `requestAnimationFrame` **не тикает** в headless/фоновой вкладке: фон-таблица не обновляется.
  Для проверок есть хук `window.__bgDraw()` (принудительный кадр).
- `vision_analyze` не работает (HTTP 404: уходит в Gemini-бэкенд с именем модели glm-5.3; 21.11).
  Облачное зрение: qwencloud-квота исчерпана до 16.12.2026 (429). Запас — LM Studio:
  `POST http://localhost:1234/v1/chat/completions`, модель `gemma-3-4b-it`, PNG как base64
  `data:` URL. Модель **слабая и противоречивая**: путает фоновую сетку с элементами сцены,
  галлюцинирует тексты. Перепроверять аналитикой по координатам и `measureText`.
- Объективный замер ширины текста: в браузере `canvas.getContext('2d').measureText()`
  с нужным font — даёт ширину в мировых юнитах.
- `motion.mjs` после правок прогонять обязательно: он поймал наезд таблички на голову
  (`head-covered`) и поймает «сломанный локоть»/скольжение стоп.
- Playwright живёт в scratch и **удаляется при чистке**: переустановка
  `mkdir scratch/pw && cd $_ && npm i playwright@1.56.1 && npx playwright install chromium`.

**Фоновая таблица панели**
- Рисуется отдельным canvas (`BG_JS` в сборщике), ячейки 7×5, значения тикают каждые 0.9 с
  с жёлтой подсветкой, края панели закрыты радиальной маской (иначе ячейки выглядят обрезанными).
- Подсветка слов по cue: `window.bgSetWords(words, startTime, audioEl)` /
  `window.bgClearWords()`; слова идут с интервалом 0.8 с. Конфиг ячеек — `WORD_CELLS`
  в `BG_JS`; список слов — в `meta.json` урока (ключ `words`).

**⚠ ЗОНА ГЕККОНА (обязательное ограничение для всех сцен).** Оверлей геккона в правом верхнем
углу панели занимает в мировых координатах примерно **x от +132 до +158, y от −139 до −118**.
Ни один элемент сцены не должен попадать в этот прямоугольник. На этом попадались не раз:
`ax2-names` (карточка «М1»), `ax2-contour` (карточка «облако»), `ax2-control`, `ax2-artifacts`,
`ax5-total`, `ax5-questions`. Правило: правый край контента — не дальше x=+130, если элемент
выше y=−118.

**⚠ `ln()` задаёт цвет САМА.** Сигнатура `ln(g, x0, y0, x1, y1, lw, col)`; внутри
`g.strokeStyle = col || C.ink`. Поэтому `g.strokeStyle = '#b91c1c'` перед вызовом `ln()`
ИГНОРИРУЕТСЯ — красный крест рисуется чёрным. Цвет передавать только 7-м аргументом
(или рисовать вручную через beginPath/moveTo/lineTo/stroke).

**⚠ Момент съёмки кадра должен учитывать тайминги ИСЧЕЗНОВЕНИЯ.** Вопросы-облачка обычно
гаснут через 2–4 с (`qK = E.back(seg(T,t0,t1)) * (1 - seg(T,t2,t3))`), поэтому кадр на t=4.5 с
выглядит «без облачка», хотя в анимации оно есть. Для QA снимать на t≈1.2–3.6 в зависимости
от сцены (смотреть `seg(...)`-окна в коде). Жесты-подъёмы руки тоже короткие: например
в `ax1-cells` рука поднимается четыре раза на 0.5–3.5 с, кадр на 4.5 с — уже с опущенной рукой.

**Подписи не должны лечь на фигуру.** Фигура в центре (x=0) занимает полосу примерно −20…+20
по x и −114…0 по y: любой `text()` в этой зоне налезет на тело. Подписи уносить в стороны
(например, x=±100) или вниз (y≈−40).

**⚠ Окончания строк: как проверять LF на самом деле.** `scenes.js` должен быть в LF
(`.gitattributes` это задаёт). Проверять командой `grep -c $'\r' file` в git-bash НЕЛЬЗЯ:
`$'\r'` там не раскрывается, grep получает шаблон `\r` и трактует его как букву «r»,
поэтому счётчик равен почти числу строк — выглядит как «весь файл в CRLF», хотя это не так.
Достоверная проверка — считать байт 0x0D:
```bash
python -c "p='courses/.../scenes.js'; print(open(p,'rb').read().count(b'\r'))"
```
Если CR действительно появились (субагенты на Windows могут перезаписать файл с CRLF),
лечится так: `python -c "p='...'; d=open(p,'rb').read(); open(p,'wb').write(d.replace(b'\r\n',b'\n'))"`.

**⚠ Анализатор границ знает не все хелперы.** `tools/check_scene_bounds.py` парсит
типовые вызовы (`rr`, `text`, `signCard`, `fileCard`, `numCard`, `circle`, `tickBadge`,
`bubble`, `ln`, `sparks`, `words`, `pivotGrid`, `cubeGrid`). Локальные хелперы урока
со своими размерами (`slot`, `kzfpCard`, `checklistSheet`, `dashRect` и т.п.) он НЕ видит —
поэтому «0 находок» не означает «всё в пределах», а только «известные анализатору элементы
в пределах». После правок обязательны ещё motion-прогон и визуальный QA-кадр.

**⚠ Regex для аргументов с вложенными запятыми.** В вызовах вида
`sparks(g, x, y, seg(T, 3.4, 4.0), 12, 5)` шаблон `[^,]+` на месте 4-го аргумента
сопоставится с «seg(T», а числом после него окажется `3.4` вместо настоящего радиуса `12`.
Для таких вызовов брать последние числа перед закрывающей скобкой: `.*?,\s*(NUM)\s*,\s*(NUM)\s*\)`.
