# Квизы курса ai-excel: импорт и настройка в Moodle

Банк вопросов собирается скриптом `tools/build_moodle_quizzes.py` из трёх источников:

| Источник | Что в нём |
|---|---|
| `datasets/passports.json` | контрольные числа по вариантам A/B/C (единственный источник цифр) |
| `assessments/numeric_items.json` | 42 вариант-специфичных вопроса: 39 числовых, 1 короткий ответ, 2 calculated |
| `assessments/items_situational_b1-b3.json`, `_b4-b6.json` | 28 общих ситуационных вопросов |

Пересборка (после любой правки вопросов или датасетов):

```bash
cd C:/Users/Olga/harness
python tools/build_moodle_quizzes.py            # собрать XML + проверки
python tools/build_moodle_quizzes.py --check    # только проверки, файлы не писать
```

Скрипт сам проверяет: все ключи находятся во всех трёх вариантах, сумма баллов на вариант = 114
(как в блупринте), XML well-formed, нет запрещённых слов («Excel», бренды), у каждого варианта
ответа есть feedback, у каждого неверного — misconception. При любой проблеме — ненулевой код возврата.

## Файлы для импорта

| Файл | Содержимое | Категории |
|---|---|---|
| `moodle/ai-excel_bank_common.xml` | 28 ситуационных (общие для всех вариантов) | `$course$/top/…/Блок N/Общие` |
| `moodle/ai-excel_bank_variant_A.xml` | 42 вопроса варианта A | `$course$/top/…/Блок N/Вариант A` |
| `moodle/ai-excel_bank_variant_B.xml` | 42 вопроса варианта B | `…/Вариант B` |
| `moodle/ai-excel_bank_variant_C.xml` | 42 вопроса варианта C | `…/Вариант C` |

Импортировать **все четыре файла**: `Управление курсом → Банк вопросов → Импорт →
формат «Moodle XML»`. Порядок не важен, категории создаются автоматически.

## Сборка шести квизов

Квиз строится не перечислением вопросов, а **слотами по категориям** — это даёт
перемешивание и защиту от передачи ответов между вариантами.

| Квиз | Категории вопросов | Порог | Баллы |
|---|---|---|---|
| Блок 1 (урок 1) | Блок 1/Общие + Блок 1/Вариант X | 70% | 10 |
| Блок 2 (урок 2) — **допусковый** | Блок 2/Общие + Блок 2/Вариант X | **80%** | 16 |
| Блок 3 (уроки 3–4) | Блок 3/Общие + Блок 3/Вариант X | 70% | 20 |
| Блок 4 (уроки 5–6) | Блок 4/Общие + Блок 4/Вариант X | 70% | 19 |
| Блок 5 (уроки 7–8) | Блок 5/Общие + Блок 5/Вариант X | 70% | 21 |
| Блок 6 (урок 9) — итоговый | Блок 6/Общие + Блок 6/Вариант X | 70% | 28 |

Настройки каждого квиза (план V2, строки 37, 195, 316):
- Попытки: **не ограничены**, оценка — **высшая за попытки**.
- Проходной балл: из таблицы выше; для блока 2 — 80%, это допуск к блокам 3–6
  (`Ограничение доступа → Оценка ≥ 80%` на квизе блока 2 для всех последующих).
- Перемешивание вопросов и вариантов ответа: **включено** (уже задано в XML: `shuffleanswers`).
- Режим оценки: «Интерактивный» не обязателен; penalty = 0, поэтому режим по умолчанию
  («Отложенная обратная связь») работает корректно.
- Обратная связь: в XML заданы feedback на каждый вариант, correctfeedback,
  partiallycorrectfeedback и incorrectfeedback — они заменяют разбор преподавателя.

## Варианты A/B/C и группы

Числа в вопросах зависят от варианта датасета, поэтому студент должен видеть **только свой**
вариант (план V2, строки 18, 201, 325):

1. Создать три группы курса: `Вариант A`, `Вариант B`, `Вариант C`.
2. Выдать студенту его вариант при записи (элемент «Выбор группы» в нулевом разделе).
3. В каждом квизе блока N сделать три отдельных экземпляра или один квиз с ограничением доступа:
   `Ограничение доступа → Группа → Вариант X`. Проще всего — три экземпляра квиза
   (`Блок 3 — вариант A/B/C`), каждый ссылается на свою категорию вариантов и на общую.
4. Файлы датасета студент тоже берёт из папки своего варианта: `datasets/variant_A|B|C/`.

## Допуски числовых ответов

- Деньги, проценты, расчётные значения: **±0,5%** (план V2, строка 33). В XML это поле
  `<tolerance>` = 0,005 × эталон.
- Счётчики (число строк, кодов, колонок, дублей): **точное совпадение**, допуск 0.
  Количество строк либо верное, либо нет — половина дубля не удалена.
- Короткий ответ (месяц кассового разрыва): регистр не учитывается (`usecase = 0`).
- Единицы измерения (`<units>`) намеренно не используются: единица названа в тексте вопроса,
  иначе Moodle требует ввода единицы и ломает автопроверку.

## Calculated-вопросы (только блок 6)

Два вопроса с рандомизацией — у каждого студента свои числа в условии:

| id | Что считает | Переменные | Формула ответа |
|---|---|---|---|
| `c-b6-01` | выручка строки | `q` 1…25, `p` 400…18000, `d` 0…30 | `{q}*{p}*(1-{d}/100)` |
| `c-b6-02` | база мини-бюджета | `s` 600000…18000000 | `{s}/6` |

Допуск относительный (`tolerancetype = 1`) 0,5%; по 10 наборов значений на переменную,
наборы детерминированы (seed от id вопроса), поэтому пересборка не меняет уже выданные варианты.

⚠ **Требует проверки на реальном Moodle.** Формат `calculated` в Moodle XML сложнее остальных
типов (dataset_definition, dataset_items, tolerancetype). Структура собрана по формату Moodle,
но без импорта в живой сервер гарантировать принятие файла нельзя. Проверить так: импортировать
`ai-excel_bank_variant_A.xml` в тестовый курс и открыть оба вопроса в блоке 6 — переменные должны
подставиться в текст, а ответ считаться по формуле. Если Moodle откажется принимать calculated,
запасной путь — собрать банк без них: в `numeric_items.json` поменять `"type": "calculated"`
на `"numerical"` с фиксированным значением, либо удалить эти два вопроса и поднять баллы
соседних (тогда сумма блока 6 должна остаться 28).

## Ключи ответов

`assessments/answer_key.md` — ключи по всем трём вариантам с расчётом и источником каждого числа.
Ключи построены независимым пересчётом из исходных файлов, а не переписыванием из паспорта;
расхождения помечены `[VERIFY]`. Файл ключей студентам не выдаётся.

## Что осталось сделать вручную в Moodle

1. Импорт четырёх XML.
2. Создание 6 × 3 = 18 экземпляров квизов (или 6 квизов с групповыми ограничениями).
3. Привязка групп A/B/C и элемента «Выбор группы».
4. Бейджи: за каждый блок — бейдж при «квиз ≥ 70% + артефакт сдан» (план V2, строка 37),
   блок 2 — бейдж «Хранитель данных» при ≥ 80%.
5. Элементы «Задание» для портфеля: без ручной оценки, фиксируют только факт сдачи
   (план V2, строка 34).
