**Результат фикса:** `build_moodle_quizzes.py` — добавлены `fmt_decimal` (полное число без
экспоненты: `5742912.5`, целые — без дробной части) и `fmt_ru` (`5 742 912,50 р.`); ответ —
`fmt_decimal`, feedback — `fmt_ru`; заодно `<minimum>/<maximum>` calculated-вопросов выведены
без `%g`-нотации. 4 банка перегенерированы; `verify_quiz_keys.py`: 135 значений, 0 расхождений;
экспоненты `[0-9]e[+-][0-9]` во всех 4 XML — 0; passports.json не менялся.

`2.79156e+07` — **37 ответов в каждом варианте** (111 студенческих вопросов суммарно;
в `ai-excel_bank_common.xml` их нет — там целые числа).

1. **Потеря точности:** `5.74291e+06` = 5 742 910, эталон — 5 742 912,50. Допуск ±0,5%
   поглощает разницу, зачёт работает, но «эталонное значение» в feedback противоречит
   числу в карточке урока — на курсе, который держится на «до копейки».
2. **UX:** студент видит «5.74291e+06 р.» — нечитаемо.

Фикс: при генерации XML форматировать ответ полным десятичным числом (`5742912.5`),
в feedback — русским форматом («5 742 912,50»). Значения идут из passports по `key_path`,
перегенерация дешёвая. После перегенерации — повторить проверку ключей.
